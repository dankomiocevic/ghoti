Benchmarks · Ghoti v0.3.0

Sub-millisecond answers from a 2-core, 1 GiB server.

Ghoti ran alone on an AWS t4g.micro, a small burstable Graviton instance, and a separate, bigger machine sent the load over the network. Every request was checked, and every number below can be reproduced with ghoti-bench.

Setup

A small server, a big load generator.

Both instances run in the same subnet of one availability zone in AWS us-west-2. The generator is much bigger than the server, so the numbers measure Ghoti, not the benchmark.

Load generator

c7g.xlarge

4 Graviton3 cores, running ghoti-bench. A run only counts if the generator stayed under 80% CPU.

1, 100 or 1,000 TCP connections →

Server

t4g.micro

2 Graviton2 cores, 1 GiB of memory, unlimited CPU credits. The released v0.3.0 linux/arm64 binary, checked against the release checksums.

  • One request in flight per connection. Each connection sends a request, waits for the whole answer, checks it, and only then sends the next. That's the only way Ghoti supports.
  • All connections opened first and kept open for the whole run. A warm-up runs before every measurement and isn't counted.
  • Two clocks. The generator times every round trip, network included. Ghoti's own Prometheus histogram times each request inside the server.
  • Strict validity. A run counts only if no connection dropped, there were no errors, and the correctness checks passed.

Over 127,000 requests per second, still under a millisecond at the median.

Time inside Ghoti

A few microseconds per request.

Ghoti's own metrics time each request from the moment the complete request arrives until the answer is written to the connection. Almost all of a sub-millisecond round trip is the network, the operating systems and the client.

These cover every request of each session, warm-ups and all connection counts included. The histogram's smallest bucket is 50 µs, so the shares below are bucket boundaries.

1,000 connections

Throughput holds; requests wait their turn.

With 1,000 connections the server still served over 110,000 requests per second, using 88 to 90% of its 2 cores. The median round trip rises to about 8.4 ms. Ghoti isn't slower per request; 1,000 clients that each keep one request waiting share the same rate, so each waits about 1,000 / 112,647 ≈ 8.9 ms for its turn, which matches the measured average.

Correctness

Fast only counts if it's right.

Every memory read was compared byte by byte with the value the slot holds. Counters and token buckets change on every request, so they were checked after each run.

Atomic counters

Read back after each run, every counter held exactly the number of increments the benchmark sent: nothing lost, nothing applied twice. That held in all 6 runs, up to 4,716,734 increments with 100 connections.

Token buckets

Under constant load, each bucket handed out every token it refilled and never more than it can hold plus its refills. For example, the shared bucket at 1,000 tokens per second gave out exactly 30,000 tokens in the 30-second window with 100 and 1,000 connections.

Zero errors

All 21 runs finished with 0 errors over 255,244,437 requests, and every connection stayed open for the whole run.

Reading these numbers

What they do and don't tell you.

  • Your network decides the round trip. Both instances sat in one availability zone, the shortest network EC2 offers. Expect a different round trip from yours. The time inside Ghoti doesn't depend on the network.
  • This is version 0.3.0 on one instance type, with the plain-text standard transport over TCP and no TLS. The http transport, broadcast and multicast slots, and clustering weren't measured.
  • One run for most scenarios. Only memory-read has three repetitions; counters and token buckets ran once for 30 seconds each.
  • Maximums are higher. The slowest single round trip of any run ranged from 5.7 ms with one connection to 255 ms with 1,000. They are in the full table.

Reproduce it.

With AWS credentials, Go, ssh and curl, one script creates both instances, runs the benchmark, downloads the results and deletes everything it created, even when it fails. The memory session takes about an hour.

$ git clone https://github.com/dankomiocevic/ghoti-bench.git && cd ghoti-bench
$ AWS_REGION=us-west-2 GHOTI_REF=v0.3.0 scripts/ec2-bench.sh
